# 실전 문제 작성 규격 (TEST SPEC)

교재 `문법 공식 (GRAMMAR FORMULA)`에 들어갈 **실전 TEST / PART 종합 TEST / 실전 모의고사** 작성 규격.
대상: **중3~고2 내신·수능 어법**. 수준은 "중" 이상, 지문형 비중 높게.

**품질 기준 샘플: `textbook/tests/unit_u06.py` (Unit 06 수동태).** 형식·난이도·해설 길이를 이 파일에 맞출 것.

## 1. 파일 위치와 이름

| 종류 | 파일 | 문항 | 배점 |
|---|---|---|---|
| 단원 실전 TEST | `textbook/tests/unit_<모듈키>.py` | 단원 난이도별 (아래 표) | 합계 100 |
| PART 종합 TEST | `textbook/tests/part_<1~5>.py` | 20 | 합계 100 |
| 실전 모의고사 | `textbook/tests/mock_1.py`, `mock_2.py` | 25 | 합계 100 |

각 파일은 `TEST = {"title": ..., "time": ..., "items": [...]}` 하나만 정의한다. 빌드가 자동으로 찾아 넣는다.

### 단원 목록 (20단원, 모듈키 ↔ 교재 단원 번호 ↔ 문항 수)
모듈키와 단원 번호가 다르다. 반드시 모듈키로 파일을 만든다.

객관식/서술형 = 6:4 (10문항 6/4, 15문항 9/6, 20문항 12/8).

PART 범위: 1 = 01~05 / 2 = 06~08 / 3 = 09~12 / 4 = 13~17 / 5 = 18~20. 모의고사 = 전 범위.
PART 종합 TEST(part_1·2·4·5)에는 신규 단원(대명사·조동사·명사절·접속사/병렬·비교) 문항이 아직 없다 → 20문항·100점은 유지하고 일부 문항을 신규 단원 문항으로 교체한다.

### 고등 실전 TEST (2차 확장)
| 종류 | 파일 | 문항 | 수준 |
|---|---|---|---|
| 단원 고등 실전 TEST | `textbook/tests/unit_<모듈키>_hi.py` (20단원 전부) | 10 (객관식 6 / 서술형 4) | 고1~고3 내신 상위권 · 수능 어법 |
| 고등 실전 모의고사 | `textbook/tests/mock_3.py`, `mock_4.py` | 25 | 수능·고2~3 내신 |

- 빌드가 자동으로 단원 실전 TEST 뒤에 「고등 실전 TEST」, 모의고사 1·2회 뒤에 「고등 실전 모의고사 1·2회」로 넣는다.
- 고등 실전 TEST: level은 `"중"`·`"상"`만 (상 50% 이상), `hard=True` 3개 이상. **지문형 최소 5문항** (객관식 지문형 어법 ⓐ~ⓔ, 서술형 지문 속 오류 수정·조건 영작). 지문은 4~8문장, 수능 어법 지문처럼 설명문·논설문 위주.
- 고등 모의고사: 지문형 최소 15문항, 수능형 어법(밑줄 5개 중 틀린 것), 어법 맞는 것끼리 짝짓기(ⓐⓑⓒ 네모 안 고르기 → 선택지 5개 조합), 서술형 조건 영작·요약문 완성.
- 단원 고등 TEST도 해당 단원 범위만 정답 근거로 삼는다(앞 단원 섞기는 가능).

## 2. 문항 작성 API (`textbook/blocks.py`)

```python
from textbook.blocks import MC, WR

MC(prompt, options, answer, explain, level="중", points=4, passage=None, hard=False)
#   options: 정확히 5개 / answer: 1~5 정수 / passage: 지문(있으면 박스로 표시)
WR(prompt, answer, explain, level="중", points=6, lines=2, conditions=None, passage=None, hard=False)
#   conditions: ["<조건> 항목", ...] / lines: 답 쓰는 줄 수
```

- `level`: `"기본"` / `"중"` / `"상"`. `hard=True`면 [고난도] 표시.
- 인라인 마크업: `**굵게**`, `==밑줄==` (지문 속 ⓐ~ⓔ는 `==ⓐ was built==`처럼), 줄바꿈은 `\n`.
- `<br>` 같은 HTML 태그는 쓰지 말 것 (그대로 글자로 찍힌다).
- 배점 합계는 반드시 100. 객관식은 보통 3~5점, 서술형은 5~8점으로 조정한다.

## 3. 유형 구성

**객관식 (60%)**
- 어법상 틀린/옳은 것 고르기
- 옳은(틀린) 문장의 개수 (고난도) → 문장 목록은 `passage`에 `ⓐ ...\nⓑ ...`
- 밑줄 친 부분의 쓰임이 같은/다른 것
- 빈칸에 알맞은 말 / 공통으로 들어갈 말
- **지문형 어법**: 4~6문장 지문 속 ⓐ~ⓔ 중 틀린 것 (선택지는 `["ⓐ","ⓑ","ⓒ","ⓓ","ⓔ"]`)

**서술형 (40%)**: 교재의 핵심 방식인 **'한 문장 바꿔 쓰기'** 중심
- 바꿔 쓰기 (태·분사구문·가정법 도치·강조구문 등)
- 조건 영작 (단어 수·활용 단어·형태 변형 조건)
- 오류 수정 + 이유 쓰기
- 지문 속 오류 2개 찾아 고치기

**지문형 비중 (높게):** 단원 TEST ★★·★★★는 지문형(객관식+서술형 합산) **최소 4문항**, ★는 최소 2문항. PART 종합은 최소 6, 모의고사는 **최소 10**.

**난이도 분포 (단원):** 기본 20% · 중 50% · 상 30%. 고난도(`hard=True`)는 단원당 2~3개.

## 4. 내용 원칙

1. **해당 단원의 원고(`textbook/content/<모듈키>.py`)를 먼저 읽고** 그 단원의 기준 문장(ANCHOR), 변형 줄기(CHAIN), 필기 포인트를 반영한다. 서술형 1~2문항은 기준 문장을 응용한다.
2. **정답은 반드시 하나.** 객관식 오답 4개는 모두 확실히 틀리거나(정답이 '틀린 것'이면 4개 모두 확실히 옳아야) 한다.
3. **자연스러운 영어만.** `by me` 같은 어색한 수동태, 원어민이 쓰지 않는 문장 금지.
4. 지문은 **직접 창작**한다. 기출·교과서·시판 교재 지문을 옮기지 않는다.
5. 해설은 1~2줄: 핵심 근거만 쓴다. (예: "happen은 자동사 → 수동태 불가")
6. 범위 밖 문법을 정답 근거로 삼지 않는다. PART·모의고사는 앞 단원 내용을 섞어도 된다.

## 5. 작업 순서와 검증

1. 파일 하나를 쓸 때마다 `python3 -c "import sys; sys.path.insert(0,'.'); import textbook.tests.unit_u04 as t; print(len(t.TEST['items']), sum(i['points'] for i in t.TEST['items']))"` 로 문항 수·배점 합계(100)를 확인한다.
2. **모든 문항을 다시 풀어 보고** 정답·해설이 맞는지 자체 검토한다. 특히 "틀린 것 고르기"에서 정답 외 선택지가 정말 다 맞는지 본다.
3. `python3 build.py`로 전체 빌드가 에러 없이 끝나는지 확인한다. 필요 패키지: `pip install playwright python-docx pypdf reportlab pillow`, Chromium 경로 `/opt/pw-browsers/chromium`. 머리글 한글이 □로 나오면 시스템 한글 글꼴이 없는 것이니 무시해도 된다 (본문은 `assets/fonts` 사용).
4. `textbook/tests/`와 이 문서 밖의 파일은 수정하지 않는다. 엔진이나 디자인은 원래 세션이 담당한다.
